# 实验报告

主要实现了 ch4 要求中的四个系统调用 `sys_get_time`，`sys_trace`，`sys_mmap`，`sys_munmap`

## `sys_get_time`

用户程序将 `TimeVal` 变量的用户空间的 **虚拟地址** （这是由 `memory_set::from_elf` `函数创建的）传入内核，TimeVal` 的大小为 16字节，所有可能发生跨页。调用内核提供的 `translated_byte_buffer` 函数返回正确的内核空间的 **虚拟地址（直接映射）**，对虚拟地址进行逐字节复制即可。

## `sys_trace`

该函数是上面 `sys_get_time` 的简化版本，只有 1字节，所以不会发生跨页。其次，该操作是用户向用户空间 **指定的** 虚拟地址进行读写操作，所以在读写时，需要检查 PTE 对应的标志位。

函数调用统计在 `TaskControlBlock` 中维护 `BTreeMap`，在 `trap_handler` 入口统一调用函数，统计调用数。

## `sys_mmap`

这个函数较为简单，只需要检查 `prot` 是否合法，然后检查需要分配的 **内存范围** 是否已经被分配过，未分配过则执行 `insert_framed_area` 函数即可

## `sys_munmap`

判断需要取消分配的 **内存范围**，将对应的 `MapArea` 给 `drop` 掉即可。


# 问答作业

## 页表项

##### 请列举 SV39 页表页表项的组成，描述其中的标志位有何作用？

SV39 为三级页表，一个页为 $4KB$  
可以寻址 $512 * 512 * 512 * 4KB = 2^{39} = 512GB$

SV39 的 PageTableEntry 包含 8bytes (64 bits)，其组成如下：


| 位域  | 名称         | 描述                           |
| ------- | -------------- | -------------------------------- |
| 63:54 | 保留位       |                  |
| 53:10 | PPN[2:0]     | 物理页号(Physical Page Number) |
| 9:8   | RSW          | 保留给管理软件使用             |
| 7     | D (Dirty)    | 脏位                           |
| 6     | A (Accessed) | 访问位                         |
| 5     | G (Global)   | 全局位                         |
| 4     | U (User)     | 用户位                         |
| 3     | X (eXecute)  | 可执行权限                     |
| 2     | W (Write)    | 可写权限                       |
| 1     | R (Read)     | 可读权限                       |
| 0     | V (Valid)    | 有效位                         |

标志位作用

- V (Valid)​: 表示页表项是否有效。
  - V=0 时页表项无效，会触发页错误异常。
- R, W, X (Read/Write/Execute)​: 控制页面的访问权限
  - R=1：允许读取
  - W=1：允许写入
  - X=1：允许从内存页执行指令
  - R=0 且 W=1 在 risc-v 中是非法的，W = 1 时 R 也必须为 1
- U (User)​: 控制用户模式访问
  - U=1：允许 U模式 访问
  - U=0：只允许 S模式 和 M模式 访问
- G (Global)​: 全局标志，表示该页在所有地址空间都有效，切换地址空间时TLB中该页的转换不需要刷新
- A (Accessed)​: 指示该页是否被访问过
- D (Dirty)​: 脏位，指示该页是否被写入过
- RSW​: 保留给监管软件使用的两位，硬件忽略这些位

## 缺页

##### 请问哪些异常可能是缺页导致的？

- 访问 PageTable 没映射过的虚拟地址
- 访问了无效的（标志位 V=0）页表项
- 用户程序访问了（标志位 U=0）内核空间的页表项
- 访问了没有读权限的页表项（标志位 R=0）

##### 发生缺页时，描述相关重要寄存器的值，上次实验描述过的可以简略。

发生缺页时会进入 stvec 寄存器指向的 Trap 入口，陷入 S 态，此时

- scause
    - 0xC: Instruction Page Fault
    - 0xD: Load Page Fault
    - 0xF: Store/AMO Page Fault
- stval 保存触发缺页的虚拟地址写入
- sepc 指向发生缺页的指令地址

##### 这样做有哪些好处？

在内存页面被访问才实际进行页表操作，这种 Lazy 策略可以节省内存空间，避免创建不必要的页表项，减少内存开销。

##### 处理 10G 连续的内存页面，对应的 SV39 页表大致占用多少内存 (估算数量级即可)？

假设分配 512G 空间，则需要 $$(4 + 4 * 512 + 4 * 512 * 512) / 1024 / 1024 = 1GB$$ 

则 10G 空间需要 $10/512*1024 = 20MB$ 的空间

##### 请简单思考如何才能实现 Lazy 策略，缺页时又如何处理？描述合理即可，不需要考虑实现

假设我们是用 Lazy策略，则在用户程序读写一个虚拟地址时，会发生缺页异常。进入 Trap 处理程序，同时陷入 S态。我们可以通过判断 `scause` 判断异常类型，如果为缺页异常则可以获取 `stval` 保存的虚拟地址，创建 PTE。然后通过 `sret` 返回发生缺页异常时 `sepc` 所指向的的指令地址，重新返回 U态。

##### 此时页面失效如何表现在页表项(PTE)上？

修改 PTE 的标志位 V=0，使 PTE 无效。同时内核管理标志位 RSW，如将 RSW=1 表示缺页是因为我们将内存 swap 到了硬盘上？

## 双页表与单页表

##### 在单页表情况下，如何更换页表？

在 switch （切换要运行的用户程序）操作时，修改 `satp` 寄存器为相应程序的页表即可。

##### 单页表情况下，如何控制用户态无法访问内核页面？（tips:看看上一题最后一问）

设置 PTE 的标志位 U=0，使得该 PTE 只能在 S态 访问

##### 单页表有何优势？（回答合理即可）

因为切换页表时会进行 TLB 刷新，所以单页表可以减少页表的切换，减少上下文切换的开销（双页表要将用户空间切换到内核空间，而在单页表中，页表完整的包含内核数据）

##### 双页表实现下，何时需要更换页表？假设你写一个单页表操作系统，你会选择何时更换页表（回答合理即可）？

在双页表下，进行 `ecall`（系统调用）时会切换页表，触发其他硬件中断时也会切换页表（到内核空间）。总结就是进入 trap_handler 时会切换页表到内核空间，回到用户程序时，需要将页表切换到用户空间。

在单页表下，只有在切换运行的用户程序时需要切换页表。
